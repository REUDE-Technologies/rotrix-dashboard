# Database & backend data engineer — short JD

## About the role

Join the team that designs, builds, and evolves our relational data layer and its integration with the Python application (models, migrations, queries).

## Key responsibilities

- Model and document schemas (entities, relationships, constraints, indexes).
- Implement and maintain **PostgreSQL** objects and efficient **SQL**.
- Align application data access with the schema (e.g. **SQLAlchemy**-style models and sessions).
- Ship schema changes through a controlled **migration** workflow with reviews.
- Support performance and integrity (transactions, keys, basic query tuning).
- Follow secure handling of sensitive data (e.g. hashed credentials, minimal privilege).
- Support database lifecycle in **cloud** environments: managed PostgreSQL services, connectivity and access patterns, secrets/credentials handling, backups, and basic monitoring.

## Required qualifications

- Solid **SQL** and relational design fundamentals.
- Hands-on **Python** for backend or data-access code.
- Experience with an **ORM** and **Git** in a collaborative codebase.
- Practical exposure to a **public cloud** (**AWS**, **Azure**, or **GCP**) for databases or backend services: managed SQL, access control, secrets, or deployment of data-backed workloads.
- Clear written communication for schema notes and PRs.

## Preferred qualifications

- Deeper experience on one cloud as it applies to data: hosted relational databases, IAM or role-based access to data resources, networking for private or public endpoints, and secrets management.
- PostgreSQL specifics, Alembic or equivalent migrations, Streamlit or similar app stacks, Supabase or dual auth/data paths.
- **AWS:** RDS or Aurora PostgreSQL, Parameter Store or Secrets Manager, VPC/security groups, IAM database authentication where applicable.
- **Azure:** Azure Database for PostgreSQL (Flexible Server), Key Vault, private endpoints, Entra ID–aware access patterns.
- **Google Cloud:** Cloud SQL for PostgreSQL, Secret Manager, VPC connectivity (e.g. Private Service Connect or authorized networks).
- Infrastructure-as-code exposure (e.g. **Terraform**, **Bicep**, or CloudFormation) for database-related resources.
